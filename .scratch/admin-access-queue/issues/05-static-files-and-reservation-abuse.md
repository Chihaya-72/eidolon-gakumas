# 静态文件不再查门禁，排队票不能白占服务位

Status: done

来自 PR #3 审查。

## 验收

- [x] 图片、声音和字体请求不再访问后端；页面仍然检查门禁。
- [x] 门禁检查有超时，后端无响应时页面按失败关闭处理。
- [x] 轮到后过期或被放弃的浏览器票据计一次使用，反复占位的用户会排到后面。

## Comments

### 实现说明（票 05）

`frontend/src/lib/access.ts` 新增 `needsAccessCheck`，`frontend/src/proxy.ts` 用它决定是否查门禁，并给检查加 5 秒超时。`backend/src/eidolon/service_queue.py` 新增 `_forfeit` 和 `MAX_PENDING_TICKETS`。

判断题：

- 静态文件在门禁开启时也能直接访问。门禁保护的是页面和业务 API，这些文件是公开站点素材。
- 后端不可用时页面仍返回 503，而不是放行，门禁继续按失败关闭处理。
- 轮到后主动取消也计一次，否则占满 14 秒再取消就能绕过。票据带着自带密钥使用时同理，因为服务端没有在这一步验证密钥真伪。正常自带密钥的请求不申请票据，不受影响。
- 酒吧票据的资源路径仍不校验归属。票据数量有上限，实际操作会重新校验，所以不再单独处理。
