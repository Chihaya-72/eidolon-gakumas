# 新通话被拒时，旧通话已经被挂断

Status: ready-for-agent

来自 PR #3 审查，只记录，暂不修复。读代码得出，未实际复现。

## 问题

`Calls.start`（`backend/src/eidolon/call.py`）在进入 `_admit_and_start` 之前先执行 `hang_up(user_id, "left")`，这时新通话还没过排队、冷却和额度检查。函数自己的说明仍写着「放行后才挂断旧通话」。

## 复现路径

1. 用户在通话 A 中，本小时通话次数已用完，或目标角色在冷却中。
2. 从另一台设备发起通话 B。
3. 通话 A 被挂断，随后 `Admissions.call` 抛出 `OverLimit` 或 `CoolingDown`。
4. 用户两通电话都没有。合并前，被拒的替换不会影响旧通话。

全部自带密钥的通话也会走这一步，但它们本来不需要释放共享服务位。

## 验收

- [ ] 新通话被额度、冷却或容量拒绝时，旧通话继续。
- [ ] 全部自带密钥的通话在放行后才挂断旧通话。
- [ ] 回归测试覆盖额度拒绝和冷却拒绝。

修法要和票 03 一起考虑：共享密钥的替换确实需要先让出服务位。
