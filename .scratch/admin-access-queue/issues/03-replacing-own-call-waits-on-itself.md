# 替换自己的共享密钥通话时，会等自己占着的服务位

Status: ready-for-agent

来自 PR #3 审查，只记录，暂不修复。读代码得出，未实际复现。

## 问题

浏览器（`frontend/src/lib/call.ts`）拿到就绪票据后才发 `/api/offer`，而服务端收到 `/api/offer` 才挂断旧通话。旧通话占着唯一的服务位，票据就一直等不到就绪。`call.py` 里「替换时先释放服务位」的注释只对不带票据的请求成立。

## 复现路径

1. 用户用共享密钥在手机上通话。
2. 在电脑上发起新通话，或刷新页面后在旧连接被判定断开前重拨。
3. 新通话停在排队，旧通话继续，直到旧通话结束才轮到。合并前是新通话直接替换旧通话。

## 验收

- [ ] 用户替换自己的通话时不必等旧通话结束。
- [ ] 新通话最终被拒时，符合票 02 的要求。
- [ ] 回归测试覆盖「旧通话占位时，带票据替换」。
